## Overview

**LectureMind** is a web-based AI tool designed to help university students get more out of their lecture materials. It accepts an uploaded audio recording and/or PowerPoint slide deck, automatically transcribes the speech, describes slide content using image captioning, generates a concise summary, produces study flashcards, and creates a quiz — all within a clean, accessible web interface.

The system is built around three pre-trained AI models operating on different data modalities (audio, image, and text), fulfilling the CM3020 Final Year Project requirement of orchestrating multiple models to achieve a well-defined goal.

---

## Goals & Non-Goals

### ✅ Goals
- Automatically transcribe lecture audio into accurate text using a speech-to-text model
- Generate meaningful study flashcards from lecture transcripts using a local language model
- Summarise long transcripts into digestible key points
- Extract content from lecture slides using image captioning (BLIP)
- Deliver results through a clean, self-built web interface (Flask + HTML/CSS/JS)
- Complete processing within a reasonable time for a typical 1-hour lecture

### ❌ Non-Goals
- Real-time live transcription during a lecture (batch processing only)
- Integration with university LMS platforms (e.g. Moodle, Canvas)
- Mobile app development
- Multi-user accounts or cloud storage of transcripts
- Support for non-English lectures (v1)

## User Personas

| Persona | Description | Primary Needs |
|---|---|---|
| Full-time student | Attends lectures, reviews recordings before exams | Flashcards, summary, fast turnaround |
| Part-time / working student | Misses some lectures, relies on recordings | Accurate transcript, key point summary |
| Student with accessibility needs | Needs text-based alternatives to audio | High-quality transcript, readable output |
| Study group organiser | Prepares shared study materials | Downloadable flashcards, clean formatting |

## System Architecture Overview

```
User (Web Browser)
      │
      ▼
Flask Web Server (webapp.py)
      │
  ┌───┴──────────────────────────────────────┐
  │                                          │
  ▼                                          ▼
Input Processing Pipeline              Static Web Frontend
  ├── Audio → Whisper (transcription)    ├── upload.html
  ├── Slides → python-pptx + BLIP        ├── results.html
  │             (text + image caption)    └── style.css
  └── Transcript + Slide Content
        → Ollama/llama3.2
            ├── Summary
            ├── Flashcards
            └── Quiz
      │
      ▼
JSON Response → Displayed in Browser
```

**Recommendation:** Python 3.11+ with Flask for the backend. Whisper and BLIP run via HuggingFace transformers; Ollama runs as a local server. Audio and slide uploads are independent — the user may provide one or both. No cloud API costs for core functionality.

## Feature Specifications

### F1: Audio Transcription
**Purpose**
Convert uploaded lecture audio or video files into accurate text, forming the foundation for all downstream processing.

**User Flow**
```
User uploads audio file (mp3, mp4, wav, m4a)
  → Flask receives file
  → Whisper model transcribes audio
  → Transcript displayed in Transcript box
  → Transcript + slide content passed to F2, F3, F5
```

**Display Format**
```
📝 Transcript

Everything in this world is made up of matter and those matters
behave with each other in certain ways. That is the foundation
of chemistry...
```

**Tech Approach**

Model: OpenAI Whisper (`base` model)
- Runs fully locally, no API key or internet required
- Supports mp3, mp4, wav, m4a, and most common audio formats
- Automatically detects language
- `base` model chosen for speed/accuracy balance on CPU hardware

Model selection rationale (to be documented in report):

| Model | Size | Speed (CPU) | Accuracy | Decision |
|---|---|---|---|---|
| tiny | 39MB | Very fast | Lower | Rejected — too many errors |
| base | 74MB | Fast | Good | ✅ Selected |
| small | 244MB | Slow | Better | Rejected — too slow on CPU |
| medium | 769MB | Very slow | High | Rejected — impractical |

Caching: Whisper model loaded once on server start to avoid reload delay per request.

**Data Fields**

| Field | Required | Source |
|---|---|---|
| Raw transcript text | ✅ | Whisper |
| Detected language | ✅ | Whisper |
| Word-level timestamps | ⚡ Optional | Whisper (verbose mode) |

### F2: Flashcard Generation
**Purpose**
Automatically generate study flashcards from the lecture transcript and/or slide content, saving students hours of manual note-taking.

**User Flow**
```
Transcript and/or slide content received
  → Sent to Ollama with structured prompt
  → LLM generates Q&A flashcards
  → Flashcards displayed in Flashcards box
```

**Display Format**
```
🃏 Flashcards

Card 1
Front: What is chemistry?
Back: The study of how matter interacts with other matter.

Card 2
Front: What are the building blocks of all matter?
Back: Atoms and molecules.

Card 3
Front: Why does matter behave differently with other substances?
Back: Due to differences in chemical properties and atomic structure.
```

**Tech Approach**

Model: Ollama with llama3.2 (runs locally)
- Free, open-source, no API costs
- Runs entirely on local machine
- llama3.2 chosen over larger models for speed on CPU hardware

Prompt design (current):
```
Generate 5 flashcards from the following lecture content.
Format each flashcard as:
Front: [question]
Back: [answer]

Lecture Content:
Transcript:
{transcript}

Slide Content:
{slide_content}
```

Note: Prompts evolved during development. The current prompt generates 5 flashcards independently (not combined with summary) using both transcript and slide content when available. The app passes `transcript` and `slide_content` to the flashcard function, which builds a combined context string.

Model selection rationale (to be documented in report):

| Model | Size | Quality | Speed | Decision |
|---|---|---|---|---|
| llama3.2 | 2GB | Good | Fast | ✅ Selected |
| llama3 | 4.7GB | Better | Slow | Rejected — too slow |
| mistral | 4.1GB | Good | Medium | Considered — future option |

**Data Fields**

| Field | Required | Source |
|---|---|---|
| Flashcard front (question) | ✅ | Ollama |
| Flashcard back (answer) | ✅ | Ollama |
| Number of cards | ✅ | Currently fixed at 5 (future: user-configurable) |

### F3: Lecture Summarisation
**Purpose**
Generate a concise paragraph summary of the lecture content (transcript and/or slides), giving students a quick overview before diving into flashcards.

**User Flow**
```
Transcript and/or slide content received
  → Sent to Ollama with summarisation prompt
  → Summary displayed in Concepts & Summary box
```

**Display Format**
```
📋 Summary

This lecture introduces the fundamental concept of chemistry,
explaining that all matter in the world interacts with other
matter in unique ways. The session covers the basic definition
of chemistry and sets the foundation for understanding atomic
and molecular interactions.
```

**Tech Approach**

Uses the same Ollama/llama3.2 model as F2. The summary is generated via an independent Ollama call (not batched with flashcards), using a dedicated prompt that combines transcript and slide content when available.

Prompt (current):
```
Summarise the following lecture content in 2-3 sentences.
Focus on the main topic and key takeaways.

Lecture Content:
Transcript:
{transcript}

Slide Content:
{slide_content}
```

### F4: PowerPoint Slide Processing
**Purpose**
Extract structured content from uploaded lecture slides — both raw text and image captions — to enrich study materials alongside the audio transcript.

**User Flow**
```
User uploads .pptx file (optional, alongside audio)
  → python-pptx extracts text from each slide
  → Slide images rendered and passed to BLIP model
  → BLIP generates a caption describing each slide image
  → Combined text + captions displayed in Slides section
  → Slide content passed to F2, F3 alongside transcript
```

**Display Format**
```
📊 Slide Content

Slide 1 — "What is Matter?"
  Text: Everything in this world is made up of matter...
  Caption: A chalkboard with chemical formulas and atomic diagrams.

Slide 2 — "Atomic Structure"
  Text: Atoms are the building blocks of matter...
  Caption: Diagram showing nucleus with protons and neutrons,
          surrounded by orbiting electrons.

Slide 3 — "Chemical Bonds"
  Text: Covalent bonds form when atoms share electrons...
  Caption: Illustration of two hydrogen atoms sharing electrons.
```

**Tech Approach**

Model: Salesforce `blip-image-captioning-base` (via HuggingFace transformers)
- Free, open-source, runs locally
- ~1GB model, loaded once at server start
- Generates natural-language descriptions of slide images
- Complements python-pptx text extraction

Implementation:
```python
from transformers import pipeline
captioner = pipeline("image-to-text",
    model="Salesforce/blip-image-captioning-base")

# For each slide, extract text and render to image

import io
from PIL import Image

prs = Presentation("slides.pptx")
slide_data = []
for slide in prs.slides:
    # Extract text
    slide_text = ""
    for shape in slide.shapes:
        if shape.has_text_frame:
            slide_text += shape.text + "\n"
    # Render slide to image → caption via BLIP
    # (Caption generated server-side from rendered slide PNG)
    caption = captioner(slide_image)[0]["generated_text"]
    slide_data.append({"text": slide_text, "caption": caption})
```

Model selection rationale (to be documented in report):

| Model | Size | Caption Quality | Speed | Decision |
|---|---|---|---|---|
| blip-image-captioning-base | 990MB | Good | Fast (GPU) / Moderate (CPU) | ✅ Selected |
| blip-image-captioning-large | 1.5GB | Better | Slower | Considered — if GPU available |
| vit-gpt2-image-captioning | 600MB | Adequate | Fast | Rejected — lower caption quality |

**Data Fields**

| Field | Required | Source |
|---|---|---|
| Slide number | ✅ | python-pptx |
| Slide text content | ✅ | python-pptx (text frames) |
| Slide image caption | ✅ | BLIP model |
| Slide title (if available) | ⚡ Optional | python-pptx (title shape) |

### F5: Quiz Generation
**Purpose**
Generate a 5-question quiz from the lecture content (transcript and/or slides) to help students test their understanding.

**User Flow**
```
Transcript and/or slide content received
  → Sent to Ollama with topic extraction prompt
  → LLM returns 5 distinct lecture topics
  → For each topic, a separate Ollama call generates
    one question with an answer line
  → All 5 questions displayed in Quiz box
```

**Display Format**
```
📝 Quiz

Question 1: What is the central concept in chemistry?
Answer: _______________________________________________

Question 2: How do atoms form chemical bonds with other atoms?
Answer: _______________________________________________
```

**Tech Approach**

Model: Ollama with llama3.2 (runs locally)
- Two-stage generation to guarantee 5 distinct, non-repeating questions
- Stage 1: Extract 5 distinct topics from the combined lecture content
- Stage 2: Generate 1 question per topic, each with an answer line
- Retry logic: if the answer line is missing, re-prompt (max 2 attempts)

Implementation flow:
```
def generate_quiz(transcript, slide_content):
    # Stage 1: Extract 5 topics
    topics = llm.invoke(topic_prompt)
    # Stage 2: Generate one question per topic
    for topic in topics:
        response = llm.invoke(question_prompt.format(topic))
        # Verify answer line present; retry if missing
        if "Answer:" not in response and attempts < 2:
            response = llm.invoke(retry_prompt)
        quiz.append({"question": response, "topic": topic})
```

Total Llama calls: 6 (1 topic extraction + 5 questions). Slower but reliably produces 5 distinct questions.

**Data Fields**

| Field | Required | Source |
|---|---|---|
| Question text | ✅ | Ollama (stage 2) |
| Answer line placeholder | ✅ | Ollama (stage 2) |
| Topic label | ✅ | Ollama (stage 1) |

### F6: Downloadable Study Pack
**Purpose**
Allow students to download their transcript, summary, and flashcards as a text file for offline study.

**User Flow**
```
Results displayed on screen
  → User clicks "Download Study Pack"
  → .txt file downloaded containing:
      - Transcript
      - Slide content
      - Summary
      - Flashcards
      - Quiz
```

**Tech Approach**

Generated server-side in Flask and returned as a file download response:
```python
from flask import Response

@app.route("/download", methods=["POST"])
def download():
    content = f"TRANSCRIPT\n{transcript}\n\nSUMMARY\n{summary}\n\nFLASHCARDS\n{flashcards}"
    return Response(content, mimetype="text/plain",
        headers={"Content-Disposition": "attachment;filename=study_pack.txt"})
```

## Tech Stack

| Layer | Choice | Reason |
|---|---|---|
| Language | Python 3.11 | Best ecosystem for AI/ML models |
| Web framework | Flask 2.x | Lightweight, easy to learn, industry standard |
| Speech-to-text | OpenAI Whisper (base) | Free, local, highly accurate |
| Language model | Ollama + llama3.2 | Free, local, no API costs |
| Image captioning | Salesforce BLIP (HuggingFace) | Free, local, ~1GB model, rich caption quality |
| Slide parsing | python-pptx | Extracts text and embedded images from .pptx |
| Frontend | HTML5 + CSS3 + Vanilla JS | Full custom build, no frameworks |
| Hosting | Local (localhost:5000) | FYP scope; can deploy to Railway/Render later |

## AI Models Used

| # | Model | Task | Data Type | Source |
|---|---|---|---|---|---|
| 1 | OpenAI Whisper (base) | Speech → Text | Audio | openai/whisper |
| 2 | Salesforce BLIP | Image → Text caption | Image (slides) | huggingface.co/Salesforce/blip-image-captioning-base |
| 3 | Ollama llama3.2 | Text → Summary + Flashcards + Quiz | Text | ollama.com |

All three models operate on different data domains (audio, image, text), satisfying the CM3020 requirement for models operating across multiple data spaces.
